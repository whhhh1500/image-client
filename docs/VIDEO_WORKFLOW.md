# 短剧视频工作流

短剧视频与小说漫画是两个独立生产域，不共享分镜契约。

## 短剧视频

```text
VideoMarkdownWorkspace
  共享小说章节/脑洞 → 改编规划 → 剧本 → 视频锚点 → 视频分镜 → 质检
                         ↓
                 视频分镜 Markdown
                         ↓
                    VideoPanel
                         ↓
              独立镜头视频资产 → 手动拼接
```

- `src/components/video/VideoMarkdownWorkspace.tsx`：与小说漫画相似的分阶段 Markdown 工作台。
- `src/store/useAgentStore.ts`：五个 Agent 的定义、Prompt 版本和固定执行顺序。
- `src/lib/video/storyboard.ts`：唯一视频分镜 Markdown 契约、严格解析、序列化和每镜生成参数提取。
- `src/components/video/VideoStoryboardEditor.tsx`：视频分镜查看与编辑。
- `src/pages/VideoPanel.tsx`：每镜 Prompt/时长编辑、生成、历史选择和手动拼接。
- `src/lib/generateVideo.ts`：逐镜调用、独立持久化和显式拼接。
- `src-tauri/src/video.rs`：zzone Provider 请求、模型能力校验、轮询和下载。

视频分镜只接受固定标题结构的 Markdown，不解析 JSON、表格或其他隐式格式。

## Provider 适配边界

从 Toonflow Provider 中吸收的是能力声明和交互思想，不复制它的请求格式：

- 模型先声明生成模式、合法时长、分辨率、画幅和参考素材上限，UI 只提供当前模型可用选项；
- `resolution`、`aspect_ratio`、时长和参考素材均作为结构化请求参数，不能用 Prompt 代替；
- 首帧驱动由参考图决定画面几何，不额外提交可能与参考图冲突的 `aspect_ratio`；
- 创建任务成功后固定使用同一个 task ID 轮询。429、5xx 和瞬时网络错误只退避重试查询，不自动重新创建付费任务；
- 下载成片遇到 429、5xx 或瞬时网络错误时也只重试同一个 task ID 的 `/content`，不重新生成；
- 一个 Markdown 镜头严格对应一次 Provider 创建请求和一个独立视频资产。超出模型时长范围时直接阻断，不自动拆镜；
- 托管图像、视频参考只接受当前项目内能够解析为无凭据公网 HTTPS URL 的媒体资产。本机、内网、链路本地、带用户名密码的 URL 会在前端和 Rust 两层阻断；当前项目的本地**图片**可通过资产 ID 或 canonical 来源身份由 native 解析为临时 data URL，锚点 ID 和文本资产不能冒充媒体引用；本地视频仍须先托管。
- Drama Video V2 与 Fast 的图片、视频、音频参考总数按 Provider 文档限制为 12；桌面工作区当前仍不开放音频参考；
- Provider 返回的 task ID 会保存到视频资产 ID 和 `providerTaskId` 溯源字段，便于排障和核对；
- `/v1/models` 返回但本地没有可靠能力定义的模型会显示为不可生成，不套用臆测参数。

Toonflow 的插件会根据供应商把 base64 参考素材和元数据翻译成不同请求体，并把结果转回 base64。当前项目面向 zzone 的 `/v1/videos` 异步协议：前端提交统一参数，Rust 创建任务、持有 task ID、轮询并下载 MP4，然后将每镜结果独立写入 SQLite 资产历史。因此两者共享“能力驱动”的设计，但媒体传输、状态持久化和错误恢复不能混用。

## Markdown 修改与 LLM 优化

短剧工作区支持直接上传本地 MP4、WebM、MOV，或从当前项目视频资产中选择“视频作品参考”。这些参考与小说正文、图片资产和最终视频结果分开管理，按短剧工作区隔离。文本 Agent 只读取资源名称、模型、时长、镜头号和溯源信息，不声称直接观看了本地视频画面。

在视频生成页中，公网可访问且不带凭据的 HTTPS 视频可以进入 Provider `videos[]`；本地视频须先由用户明确选择托管并取得公网 HTTPS URL 才能实际引用，原本地路径只用于预览和溯源。

改编规划、剧本、视频锚点、视频分镜和质检都采用版本化 Markdown：

1. 打开任意已保存版本；
2. 手动修改，或填写优化要求后调用 LLM；
3. “AI 生成草稿”只进入未保存草稿；
4. “AI 优化”读取同一视频工作区全部已保存文字产物和媒体关联元数据；
5. 从当前阶段开始，按规划 → 剧本 → 锚点 → 分镜 → QC 的依赖顺序优化已有下游文字产物；
6. 每个阶段均先完成独立质量审查，所有联动草稿通过后才按顺序直接保存为新版本；成功路径不会停留在“需更新”标记；
7. 图片和视频媒体不自动重新生成，避免未经确认产生费用，旧媒体继续作为历史结果保留。

视频分镜优化后必须通过固定 Markdown 结构校验。一个 Markdown 镜头仍对应一次 API 请求和一个独立视频资源。

每个 Agent 草稿还可以执行独立质量审查，检查原文忠实度、剧情吸引力、视觉独特性、人物情感、物理可信度和生产可执行性。程序硬规则优先于模型评分：画幅冲突、锚点缺失、参考资产缺失、图形化伤害、伪物理、复合高风险镜头或证据不足的 QC 都会强制判为“需修改”。审查建议可一键带入 AI 优化要求；用户点击 AI 优化后，系统会对当前及已有下游文字产物完成联动优化和审查，全部通过后直接保存新版本。

工作台提供“结构化总览 / Markdown 源稿 / 并排审阅”三个平级视图。历史版本默认只读；用户必须明确选择保留旧依赖的历史分支，或创建迁移到最新依赖的草稿，系统不会把旧内容自动标记成已吸收最新上游。

## 跨章视频锚点

同一小说的每章视频锚点会读取最近几章已经确认的完整锚点快照，并结合本章原文、改编规划和剧本生成本章快照：

- 固定锚定：画风、人物基础外貌、长期场景、核心道具等跨章稳定特征；
- 剧情锚点：伤势、换装、年龄阶段、天气、场景破坏、道具持有与状态等随剧情变化的特征。

已有稳定 ID 默认继承。只有剧情明确造成可见变化时才创建新版本 ID，并记录生效章节、触发剧情、旧 ID、新 ID 和可见变化。锚点只在同一小说、较早章节之间承接，不会混入其他小说或脑洞工作区。

## 小说漫画

小说漫画继续使用自己的 Markdown 文档和漫画页生产链：

- `src/components/novel/*`
- `src/lib/comic/*`
- `src-tauri/src/comic_markdown*`
- `src-tauri/src/comic_visual*`
- `src-tauri/src/novel*`

小说漫画的“分页分镜”不会进入短剧视频分镜，短剧视频 Agent 也不会修改小说漫画分镜。

小说漫画的 AI 优化使用同样的直接联动原则：

- 作品设定 → 本章剧本 → 分页分镜 → 全部有效页 Prompt；
- 从当前产物开始依次优化已有下游文字产物，每份产物保存为独立新版本；
- 优化某页 Prompt 时默认更新当前页及后续页，也可选择本章全部有效页；
- 模型会读取当前章节正文、全部文字产物、生图注入和已有漫画图片的关联元数据；
- 漫画图片不会自动重画，旧图片保留为历史结果。

## 共享基础设施

两个生产域共享项目、小说章节/脑洞原始资料、SQLite 文档版本和来源溯源。小说章节发布为独立 text/novel 资源，可被图像与视频工作区引用；图像和视频产物、分镜格式、生成状态仍保持隔离。
